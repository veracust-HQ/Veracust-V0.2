Veracust Evaluation Policy

Please read this notice. The current policy version must be accepted before the API will process an upload.

1. Hosted evaluation processing. When you submit an audio file, your browser sends it to the Veracust evaluation API hosted on Render. The engine temporarily writes the upload to a processing file, analyzes it, and the application attempts to remove that temporary file after processing, including on error paths. Veracust does not intentionally retain uploaded audio as recordings. Temporary processing and infrastructure handling mean this is not a promise that audio never exists in server memory or temporary storage.

2. No audio in analytics. Veracust does not write audio bytes to Supabase. The evaluation database stores account identifiers, policy acceptance, access events, timestamps, verdicts, engine scores and selected technical analysis metadata. The application does not store the original filename in the evaluation record.

3. Prohibited uploads. Do not upload passwords, API keys, one-time codes, financial or account credentials, identity documents, confidential documents, source code, customer data, sensitive personal information, or any file unrelated to the audio test. Do not upload a voice recording unless you own it or have the necessary permission and rights.

4. Confidential or production data. Do not use the hosted evaluation service for confidential, regulated, customer, employee or production recordings. Contact veracust.hq@gmail.com first. A written agreement and consultation with the Veracust team are required before any such evaluation. Ask about a private deployment inside your own cloud environment.

5. Service providers. The evaluation API and account/analytics database are hosted by Render and Supabase respectively. Those providers may process operational information under their own service terms and privacy policies. Veracust's application does not intentionally retain audio, but cannot make guarantees about provider-level infrastructure beyond its configuration and controls.

6. Evaluation limitations. Results are experimental decision-support output, not proof of identity, a guarantee of authenticity, or a substitute for independent verification. Do not rely on a single result to authorize payments, account changes or other high-impact actions.

7. Usage records. Account access and analysis metadata are used to operate the evaluation service, display your activity and measure adoption. Contact the team for questions or data requests.
